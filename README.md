# Реестр розничных ПИФов России

Реестр открытых, интервальных и биржевых ПИФов: СЧА, стоимость пая и притоки по данным самих
управляющих компаний. У каждой точки ряда есть ссылка на источник, расчёты сверяются с официальными
значениями, а результат собирается в статический раздел `/pif/` в стиле algosphere.tech.

**Демо:** https://mfourks.github.io/pif-registry/pif/

Тестовое задание Алгосферы. Что собрано и что не получилось, описано в разделе [Состояние данных](#состояние-данных).

## Запуск одной командой

Нужен Python 3.12. Node, Docker, база и брокер не нужны.

```bash
python -m venv .venv
.venv/Scripts/activate   # Linux и macOS: source .venv/bin/activate
pip install -e ".[dev]"
python -m pif run
```

Команда делает всё: скачивает реестр, обходит сайты УК, разбирает файлы, считает притоки, строит
отчёт качества и собирает сайт в `dist/pif/`. Первый прогон идёт около часа: его ограничивает
один запрос в секунду на сайт, а сайт Рекорд Капитала отвечает по несколько секунд. Повторный прогон
без изменений занимает около 13 минут и ничего не скачивает. Посмотреть результат:

```bash
python -m http.server 8000 --directory dist
```

Сайт откроется по адресу `http://localhost:8000/pif/`.

| Команда | Что делает |
|---|---|
| `python -m pif run` | Полный прогон. Код 3, если отчёт качества запрещает публикацию |
| `python -m pif run --skip-geo-blocked` | То же, но без УК, закрытых для зарубежных адресов. Так работает расписание на GitHub |
| `python -m pif build` | Пересчёт и сборка сайта из накопленных данных, без обращения к сайтам |
| `python -m pif gate` | Проверка перед публикацией |
| `python -m pif fetch-raw` | Докачка сырых файлов по манифесту с проверкой SHA-256 |
| `pytest` | Тесты на настоящих фикстурах |

`PIF_BASE_PATH=/some/path/` меняет подпапку сайта. Все ссылки относительные, поэтому сборка работает
из любой подпапки.

## Как это работает

Устройство и обоснование решений описаны в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

### Реестр

Список фондов берётся из реестра Банка России `list_pif.xlsx`. В него входят открытые, интервальные и
биржевые фонды, кроме статуса «Исключён из реестра». В реестре нет ИНН УК и ISIN, поэтому:

- ИНН и сайт УК берутся из карточки участника рынка на cbr.ru по ОГРН;
- ISIN и тикер берутся из ISS Мосбиржи по номеру правил.

Ключ фонда везде один: номер правил. Он не меняется при смене названия и УК, поэтому история
фонда остаётся непрерывной.

### Сбор

Сайты обходятся параллельно, но к одному хосту идёт не больше одного запроса в секунду. User-Agent
называет инструмент и цель. Капчи, 403 и антибот-защита не обходятся, а становятся статусом фонда.

Каждый ответ сохраняется в `raw/` по SHA-256, а в манифест `manifest/sources.csv` записываются фонд,
адрес, формат, дата получения, хеш и статус. Папка `raw/` не лежит в git, её восстанавливает
`python -m pif fetch-raw`.

Повторный запуск не качает заново: ответы моложе 20 часов берутся из кэша, для остальных работают
`ETag` и `If-Modified-Since`, а КИД считается неизменным полгода. Докачка истории останавливается на
уже известной дате. Манифест и сборка сайта от этого не меняются, что проверяет тест.

### Разбор

| Вид источника | Разборщик | Пример |
|---|---|---|
| JSON API и JSON в разметке | `json_records`, `record_arrays` | Альфа-Капитал, ТКБ, Герои |
| Состояние Nuxt | `nuxt_payload` | Солид Менеджмент |
| Таблица доходности в раскрытии | `parse_returns_table` | Первая |
| Словарь `{дата: значение}` | `json_date_map`, `nested_date_map` | ААА, Контрада |
| Атрибут и переменная графика | `first_am_chart`, `js_graph_variable` | Первая, ААА |
| HTML-таблица | `html_table` | ВИМ |
| CSV | `delimited_text` | Промсвязь |

Колонки определяются по заголовкам, а не по порядку. Незнакомый формат даёт `UnknownFormatError`.
Ошибка попадает в отчёт качества и запрещает публикацию: ноль вместо значения появиться не может.

### Нормализация

По каждому фонду получается один ряд. Исправления записываются в `data/corrections.csv` с причиной:

| Что происходит | Что делаем |
|---|---|
| Пай резко изменился, а СЧА нет | Это дробление паёв: приводим прошлое к текущему масштабу, опубликованное значение сохраняем рядом |
| Значение ушло больше чем на 25 % и вернулось | Одиночный выброс: точка остаётся в данных, но исключается из расчётов |
| СЧА в других единицах | Домножаем, если соседние точки подтверждают масштаб |
| Источник изменил старое значение | Берём новое, старое пишем в журнал |
| Дневной ряд не совпал с КИД фонда | Ряд отбрасывается, остаются значения из КИД |
| Нет данных | Пропуск остаётся пропуском: на графике разрыв и штриховка |

Переиздание КИД с теми же значениями под другой датой тоже убирается и записывается в журнал.

Значения хранятся в валюте пая. В рубли они переводятся по официальному курсу ЦБ на дату точки.

### Притоки

Для каждого фонда и месяца:

```
приток = СЧА_конец − СЧА_начало × (Пай_конец / Пай_начало)
```

Второе слагаемое показывает, какой была бы СЧА без движения денег. Всё, что сверх него, принесли
пайщики. Пример: СЧА 1000 при пае 10, пай вырос до 10,5, значит без притоков было бы 1050. СЧА стала
1200, приток равен 150.

Уточнения:

- берётся последняя опубликованная точка месяца, где есть и СЧА, и пай;
- пай используется сопоставимый, поэтому дробление не создаёт ложного притока;
- в месяц завершения формирования притоком считается вся СЧА;
- если нет начальной или конечной точки, приток не считается: дорисовать его нельзя;
- у валютных фондов приток считается в валюте пая и переводится по курсу конца месяца, поэтому переоценка
  валюты притоком не считается;
- незавершённый текущий месяц не считается;
- КИД за прошлый месяц выходит в середине следующего, поэтому такие фонды показаны на свой последний отчётный
  месяц с подписью;
- выплата дохода снижает и пай, и СЧА, поэтому оттоком не считается.

Итоги по УК, типам, категориям и рынку складываются в `Decimal`. После каждого прогона сверка требует
точного равенства суммы по фондам и итогов. Разрыв запрещает публикацию.

### Самопроверка

Официальная доходность берётся из ключевого информационного документа: его формат задан Банком России,
в нём есть доходность за 1, 3, 6 и 12 месяцев. У Первой она взята из таблицы на странице раскрытия.
По последнему документу каждого фонда считается доходность по собранному ряду на те же даты.
Расхождения больше 0,5 п. п. попадают в `data/quality_report.json` и на сайт вместе с причиной,
публикацию они не блокируют. Выплачивает ли фонд доход, разборщик читает из самого КИД.

Вторая проверка сильнее: дневной ряд сравнивается со значениями пая в КИД на те же даты. КИД сам
называет фонд, поэтому ошибка сопоставления страницы с фондом сразу видна.

Ручная сверка 15 случайных значений лежит в `data/manual_check.csv`. Для каждого значения исходный файл
скачан заново и прочитан другой библиотекой: все 15 совпали. Результат этой проверки лежит в колонке
`machine_check`, а колонка `checked_by` оставлена для проверки глазами.

## Источники

| Данные | Источник | Почему |
|---|---|---|
| Список фондов, статус, номер правил, УК | [Реестр ПИФ Банка России](https://www.cbr.ru/vfs/finmarkets/files/supervision/list_pif.xlsx) | Регулятор, обновляется ежедневно |
| ИНН и сайт УК | [Карточка участника рынка](https://www.cbr.ru/finorg/foinfo/) | В реестре ПИФ ИНН нет |
| ISIN и тикер | [ISS Мосбиржи](https://iss.moex.com/iss/securities.json) | Официальный источник организатора торгов |
| СЧА и пай | Сайты УК | Только там есть первичные значения |
| Месячные точки и официальная доходность | КИД на сайтах УК | Единый шаблон, обязателен для всех |
| Месячные точки при отсутствии КИД | Справка о СЧА, форма 0420502 | Отчётная форма с номерами строк |
| Курсы валют | [Банк России](https://www.cbr.ru/development/SXML/) | Официальный курс |

Агрегаторы, сайты-сравнители и платные базы не используются. Настройки по УК лежат в
[config/sources.yaml](config/sources.yaml). Адрес каждого файла есть в манифесте.

## Что не получилось

Честный список. Цифры в этом разделе взяты из последнего прогона.

**Фонды без рядов**

- **Закрытые для робота сайты.** БКС отвечает 403 и ставит антибот-защиту. У Райффайзен, Арсагеры и МКБ в robots.txt закрыт весь сайт, у ТЕТИС раздел фондов, у Озона API. Это 55 фондов. Обходить такое запрещено условием задания, статус показан. Как быть с robots.txt, описано в [вопросе 4](docs/QUESTIONS.md).
- **Фонды для квалифицированных инвесторов.** У большинства таких ИПИФ на открытых страницах нет ни таблицы, ни КИД. Это установлено обходом сайтов, а не запросом в УК, поэтому статус звучит как «не найдено», а не «не публикует».
- **Не написаны разборщики.** Ингосстрах-Инвестиции и Апрель Капитал подгружают данные скриптом, а открытые фонды Т-Капитала лежат в другом разделе. Это было вопросом времени, а не запрета.
- **ДОХОДЪ.** Дневной ряд есть, но служебный адрес закрыт в robots.txt. Поэтому по большинству фондов только последний КИД.

**Качество рядов**

- **Часть рядов месячная.** Там, где дневных значений нет в открытом HTML, ряд собран из КИД или справок о СЧА. Притокам это не мешает, но график реже. Частота видна на карточке фонда.
- **Выплаты дохода не учтены.** Доходность считается по паю, поэтому у фондов с выплатами она ниже официальной. Такие строки помечены на сайте и в отчёте. Полную доходность можно посчитать, если собирать размер выплат.
- **Причина не установлена для 2 расхождений.** Это фонды УК Рекорд Капитал: в их КИД за месяц стоит одно и то же значение, похоже на ошибку вёрстки таблицы. На сайте они помечены.
- **Ряд, сопоставленный по заголовку без КИД, проверить нечем.** Сверка с КИД работает только там, где КИД есть.

**Методика и инфраструктура**

- **Присоединённые фонды.** Закрытых за период фондов нет в действующем реестре, поэтому приток в фонд-преемник может оказаться завышен.
- **Итоги рынка неполные.** В них только фонды с данными, поэтому СЧА рынка занижена.
- **Класс активов** определяется эвристикой по названию, у части фондов это «Прочие».
- **Расписание на GitHub обновляет не все УК.** Сайты ВИМ, ВИМ Сбережения, ААА и АК БАРС отвечают адресам GitHub ошибкой 403, ещё две УК не отвечают вовсе. Расписание их пропускает, их ряды обновляются запуском из России или раннером в России (`UPDATE_RUNNER`). Дата последней точки видна на карточке фонда. Если у остальных УК не обновилось больше 10 % рядов, ворота публикацию запрещают.
- **Ручная сверка.** В `data/manual_check.csv` значения проверены программой на свежих файлах с сайтов УК. Проверку глазами должен внести человек, колонка `checked_by` для этого оставлена пустой.
